# Кампус · Расписание ЗГУ

Фронтенд в ветке `front`: Vite, React, TypeScript, Tailwind CSS и shadcn/ui.
Реализована вкладка «Свободные аудитории». «Группировка» и «Поиск» пока содержат
заглушки. Сверху находятся три вкладки и кнопка переключения темы. В «Свободных аудиториях» показана
таблица с тремя столбцами: день, время, свободные аудитории. Перед таблицей есть
поиск с подсказками и множественным выбором. Аудитории добавляются в поле метками,
которые можно удалять по отдельности. В таблице остаются интервалы, когда свободна
хотя бы одна выбранная аудитория; в строке перечислены только свободные из выбранных.
Кнопка очистки возвращает полную таблицу. Выбранные аудитории не повторяются в
подсказках. Доступны мышь, касание, клавиши ↑/↓, Enter, Escape и удаление последней
метки через Backspace в пустом поле. На телефоне метки переносятся на новые строки.
Выбранные аудитории и незавершённый текст поиска сохраняются в `localStorage`
этого браузера и восстанавливаются после обновления страницы и повторного захода.
Переключение вкладок их не очищает. Кнопка очистки удаляет и сохранённый выбор.
Если хранилище браузера недоступно, поиск продолжает работать без сохранения.
Интервалы берутся
из расписания соответствующего дня и идут по времени.

На мобильных экранах дни сокращаются до «Пн», «Вт» и т. д., начало и конец
интервала располагаются друг под другом, список аудиторий переносится на новые
строки. Три столбца сохраняются без горизонтальной прокрутки. Компоненты используют стандартное оформление shadcn/ui.

Кнопка с солнцем или луной переключает светлую и тёмную темы. Используется
стандартная палитра Neutral от shadcn/ui. Выбор сохраняется в браузере; до первого
ручного переключения тема следует системным настройкам. Тема применяется до
отрисовки приложения, чтобы избежать вспышки светлого фона.

Над вкладками показан текущий номер учебной недели по времени Красноярска.
Отсчёт ведётся с 1 сентября: неделя, содержащая эту дату, считается первой,
номер меняется по понедельникам. В разделе свободных аудиторий явно указано,
что чётность недели не учитывается.

## Структура компонентов

- `src/components/ui/` — универсальные компоненты shadcn/ui без логики расписания.
  Новые примитивы добавляются через `npx shadcn@latest add <component>`;
  алиасы настроены в `components.json`.
- `src/components/elements/` — компоненты приложения: вкладки расписания,
  раздел свободных аудиторий, поиск и таблица. Они собираются из UI-примитивов.
- `src/hooks/` — загрузка данных и сохранение состояния поиска.
- `src/lib/` — обработка расписания и общие утилиты.
- `src/App.tsx` — корневой контейнер страницы.

Оформление компонентов и адаптивность задаются Tailwind-классами в TSX.
В `src/index.css` остаются подключение Tailwind, стандартная тема Neutral
от shadcn/ui, базовые стили и настройка уменьшения анимации. `Input` и `Table` взяты из
официального реестра shadcn/ui (`new-york-v4`). Цвета, шрифты и оформление примитивов не переопределяются;
в элементах приложения остаются классы компоновки и адаптивности.

## Локальный запуск

Node.js 24, npm:

```sh
npm ci
git fetch origin data
npm run prepare:data
npm run dev
```

Скрипт читает `origin/data:schedule.json`, копирует расписание в `public/data/`
и записывает дату и SHA коммита данных. Эти файлы игнорируются Git.
Для другого ref: задайте переменную `SCHEDULE_DATA_REF` при `npm run prepare:data`.

```sh
npm test
npm run build
```

Можно задать публичный JSON-источник через `VITE_SCHEDULE_URL` в `.env.local`.
Никакие токены GitHub в браузер передавать не нужно. Исходная схема данных:
`group`, `time`, `weekday`, `lesson`, `classroom`, `course`, `semester`,
`faculty`, `education_form`, `program`.

## Публикация на GitHub Pages

1. Отправьте файлы приложения в ветку `front`.
2. В Settings → Pages → Build and deployment выберите Source: **GitHub Actions**.
3. **Отдельно скопируйте только** `.github/workflows/deploy-pages.yml` в основную
   ветку `main`, сохранив там Python-парсер и workflow обновления расписания.
   Не заменяйте содержимое `main` веткой `front`.
4. В Actions выберите «Публикация сайта» → Run workflow на ветке `main`.
   Если правило environment `github-pages` ограничивает ветки, разрешите `main`
   и `front` (Settings → Environments → github-pages).

Workflow всегда собирает код из `front`, а расписание — из `data`. По умолчанию
страница будет доступна по адресу `https://xp348.github.io/schedule-parsing/`.
Для пользовательского домена поменяйте `VITE_BASE_PATH` на `/`.

Изменения `front` запускают публикацию. Успешное завершение workflow
«Обновление расписания» на `main` также запускает публикацию через `workflow_run`.
Это нужно, поскольку push, сделанный встроенным `GITHUB_TOKEN`, сам по себе
не запускает следующий workflow по событию `push`. Для `workflow_run` файл
`deploy-pages.yml` должен находиться в основной ветке — поэтому важен шаг 3.

## Как определяется доступность

- Аудитории берутся только из имеющегося расписания. Это не полный реестр.
- «Свободна» означает отсутствие пересечения со всем интервалом строки таблицы.
  Граница окончания одного занятия может совпадать с началом следующего.
- Чётные и нечётные недели объединены: используется консервативная оценка.
- Если у аудитории есть занятие без распознанного времени в выбранный день,
  её доступность неизвестна — свободной она не показывается.
- Пробелы и некоторые опечатки в номере нормализуются: `М -401`, `М206`, `М--307`.
  Онлайн-ссылки, ЭИОС и помещения без номера исключены.
- В исходном JSON есть занятия без аудитории, а отдельные датированные листы
  уже сведены парсером к дням недели. Эти ограничения не позволяют гарантировать
  фактическую доступность помещений. Бронирований и отмен вне расписания здесь нет.

При открытии страницы загружается последняя опубликованная версия расписания.
