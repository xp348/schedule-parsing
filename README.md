# Парсинг расписания

Локальный запуск с сохранением результата и журнала:

```sh
uv sync --frozen
uv run --frozen python export_schedule.py
```

Результат сохраняется в `output/schedule.json`, журнал — в `logs/schedule.log`.
При ошибке загрузки или пустом результате экспорт завершается с ошибкой,
предыдущее расписание не перезаписывается. Журнал сохраняется и при ошибке.

## Чётность недели

Каждая запись JSON содержит поле `week_parity`:

- `"odd"` — текст занятия начинается с `н.`;
- `"even"` — текст занятия начинается с `ч.`;
- `null` — стандартная начальная пометка отсутствует или обозначения неоднозначны.

Допускаются пробелы перед пометкой и после точки, отсутствие пробела после точки
и верхний регистр. Поле `lesson` сохраняет исходный текст вместе с пометкой:
текущие потребители JSON остаются совместимыми.

Расположение ячейки, номера и диапазоны недель, даты, переносы и типы занятий
не интерпретируются. Если рядом с явным префиксом есть дополнительные условия,
`week_parity` отражает только префикс, а остальные условия остаются в `lesson`.
Составные обозначения вроде `н./ч.` или `н. Математика; ч. Физика` дают `null`.
Отсутствие пометки не означает «каждую неделю».

Пример:

```json
{
  "lesson": "н. Математика (лек) Иванов И.И.",
  "week_parity": "odd"
}
```

## GitHub Actions

Workflow `.github/workflows/update-schedule.yml` запускается по будням
каждые 30 минут с 09:30 до 18:00 включительно по Красноярску
(`Asia/Krasnoyarsk`). Возможны задержки со стороны планировщика GitHub.
Предусмотрен также ручной запуск через Actions → Обновление расписания → Run workflow.

Код читается из основной ветки репозитория. Ветка `data` создаётся автоматически
при первом успешном экспорте. Она содержит:

- `schedule.json` — итоговый список занятий;
- `schedule.log` — журнал запуска, который обновил расписание.

Коммит создаётся только при изменении `schedule.json`. Изменение журнала само
по себе не создаёт коммит. Журнал каждого запуска, включая запуски без изменений
и ошибки экспорта, загружается как артефакт `schedule-log-…` на странице запуска
Actions и хранится 30 дней.

Для включения расписания нужно отправить workflow и код в основную ветку
репозитория. Workflow использует встроенный `GITHUB_TOKEN` с `contents: write`;
правила репозитория должны разрешать ему прямой push в `data`.
При первом запуске можно вручную проверить результат через Run workflow.
